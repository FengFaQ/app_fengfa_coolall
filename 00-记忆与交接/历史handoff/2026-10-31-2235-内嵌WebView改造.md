## 根因分析

### 现象 1：外部浏览器方案从根本上是错的

我最初设计：打开系统浏览器 → 用户完成验证 → 手动复制 validate 粘贴回来。

**问题**：
- 外部浏览器是独立进程，Cookie 归浏览器管，应用**读不到**
- 手动复制粘贴不可靠，且凭证会经过剪贴板
- 即使修好 opener 插件让它能打开浏览器，**仍然拿不到凭证**

这不是插件缺失，是设计错误。

### 现象 2：dismiss 时序错误

`@dismiss="emit('retry')"` 但 `error` 没清空，
而且 `set_public_fallback` 后才重试，时序上又走了一遍验证。

---

## 修复方案：内嵌 WebView

**技术验证**：确认 Tauri 2.12.5 有 `WebviewWindow::cookies()` API，
能读到 HttpOnly 和 Secure cookie。不需要 CDP。

### 新增文件

`src-tauri/src/captcha_window.rs`：
- `open_window()` — 创建 label="captcha" 的 WebviewWindow
- `read_validate()` — 调 `cookies()` 读全部 Cookie
- `extract_validate()` — 找 validate 并 URL 解码
- 6 项单元测试

### 新增命令

| 命令 | 用途 |
| --- | --- |
| `open_captcha_window` | 打开验证窗口 |
| `close_captcha_window` | 关闭 |
| `read_captcha_validate` | 诊断用，看读到哪些 Cookie |
| `complete_captcha` | **收口**：读 Cookie → 写会话 → 重放 → 返回 |

### 关键约束（已写入 PROTOCOL.md §9.6）

1. **`cookies()` 在 Windows 同步命令里会死锁**（wry#583）
   → 必须 `async` + `tokio::task::spawn_blocking`
2. **验证窗口不给任何 IPC 权限**
   → `capabilities/captcha.json` 的 permissions 为空数组
   → 它加载远程页面，不应获得应用能力
