## 第七轮：协议实测 —— 首次遭遇 403

**背景**：我开始写协议层，实测酷安 API。

**发现链**
| 阶段 | 现象 | 判断 |
| --- | --- | --- |
| 1 | 裸 curl → 403 空 body | 以为 IP 被封（**后被证伪**） |
| 2 | 加 App 头 → 567 | 发现是 EdgeOne 拦截页 |
| 3 | 补全 UA + 9 段设备码 → 200 + 1004 | 突破 WAF |

**关键错误（记录以免重犯）**
> 我最初判断「api.coolapk.com 封了我这条宽带 IP」，错了。
> 真正原因是指纹不完整：UA 缺 `(#Build; ...)` 段与 `+CoolMarket/...` 尾巴，
> 设备码必须是 9 段 Base64 反转，不能用随机 hex。

## 第十轮：参考项目真实机制（重大纠正）

**处理**：精读 `CaptchaActivity.kt`，发现参考项目的做法是：

```kotlin
// 自己构造 HTML + 引入易盾 SDK
script.src='https://cstaticdun.126.net/load.min.js';
initNECaptcha({
  captchaId: '$id',
  onVerify: (err, data) => window.CaptchaResult.postMessage(data.validate)
})
```

**结论**：不是打开酷安验证页，是**自建页面 + 易盾 SDK + JS 桥回传**。

## 第十三轮：adb 真机取证（决定性）

**用户指令**
> 使用 adb 连接手机分析 adb connect 192.168.1.166:36481

**处理与发现**
| 项 | 结果 |
| --- | --- |
| 真机设备信息 | meizu / MEIZU 21 / Android 16 / SDK 36 |
| 真机设备串明文 | `; ; ; ; meizu; meizu; MEIZU 21; BQ2A...; null` |
| App 与 curl 的 TLS 指纹 | 同设备同 BoringSSL，套件数 15 vs 17，结果不同 |
| 用 App 有效 SESSID 打 API | 仍 1004 |

**当时结论（后被证伪）**：SESSID 与 TLS 指纹绑定。
**事后证明**：那些测试用的都是**带 padding 错误的 Token**，所以不管带什么 SESSID 都失败。
